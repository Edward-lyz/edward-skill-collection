# 怎么知道重放是对的，以及怎么知道核对是对的

重放的正确性判据不是「像某份规范」，而是**与源提交等价，除了记录在案的适配**。这句话把一个
开放问题变成了差分问题：oracle 是源分支本身，不用手写期望值。三级阶梯，每级只回答一个问题，
也各有拦不住的东西。

| 级 | 脚本 | 回答的问题 | 拦不住 |
|---|---|---|---|
| L1 存在性 | `verify_platform_contract.py` | 平台依赖的东西还在不在 | 值失真、观测点位置错 |
| L2 语义残差 | `replay_residual.py` | 选中提交的内容都落地了吗 | 语义等价但写法不同的改写 |
| L3 运行时取数 | 造流量 + `/metrics` 前后 diff | 值对不对 | 需要真实部署，分钟到小时级 |

L1 拦整块漏迁：族名漂了、探针少一条、计数器没预热、trace 行断在某一段。L2 拦手上的失误：
冲突解丢一行、折叠漏 hunk、源侧删了而重放侧还留着（双份实现）。L3 是唯一能证明值对的一级，
判据取「PD 两端该有的有、该没有的没有」这类可预期的不对称：P 侧要有 TTFT、P 侧不该有 ITL、
带 label 的计数器在空闲实例上是 0 而不是 No data。

## L2 的实账：DSv4.1 重放到社区 main

18 笔源提交 vs `main..codex/dsv41-replay-on-main-0921`，净加 5,264 / 5,269 行，残差只剩 13 行：

| 类 | 行数 | 解释 |
|---|---:|---|
| 漏迁 | 4 | 全在 `http_server.py`：`@app.get("/ready")` 别名、它的 507 分支和两行注释。社区已自己收了 `/ready`，重放时改成保留社区 handler 再叠排水，这 4 行有意不搬 |
| 新造 | 9 | 5 行是上面那个改写的新 `ready()`；4 行是整行搬家造成的假阳性（见下） |
| 该删没删 | 0 | — |

这一版检查器是改过一次的。第一版把「源侧逐笔 diff 的并集」当作源侧意图，报出 33 行漏迁；逐条
读完发现 20 行是中间态——前一笔加进去、后一笔又改掉，重放侧只有最终形态，当然对不上。改成
**加集减删集**（净意图）后降到 4 行。这件事本身说明：检查器的判据也要被检验，而检验它的唯一
办法是把每条输出都读懂。

已知盲点：**整行搬家在源侧自相抵消**。某笔把一行加在 A 处、后一笔原样移到 B 处，源侧加集与
删集各含一次、相减为空，重放侧却有一次，于是报成「新造」。所以漏迁与该删没删是承重信号，
新造是复核清单。

## 怎么知道 L1 自己是对的：变异探针

「核对通过」只有在核对会因为真缺陷变红时才有意义。`verify_mutations.py` 拿一个已通过的分支，
逐个种入**一类真实发生过的缺陷**，跑 L1，看它是否变红。变异表里每行都对应线上见过的形态，
不是凭空造的语法错。

这一轮 10 条变异跑出了核对脚本自己的一个 bug：删掉主 server 的 `@app.get("/health_forward")`
居然过了。原因是路由只按路径记 key，而 EPD 的 encode server 上也有同名路由，两个宿主并成了
一项，删一个还剩一个。改成按「上一级目录/文件名 + 路径」记 key 后变红，主 server 路由也从
3 项变成 5 项——契约同时变严了。

当前结果：8 条应拦的全部 CAUGHT，2 条登记在案的盲点 SURVIVED。

| 变异 | 结果 |
|---|---|
| 删主 server 探针路由 / 删 dummy server 自省路由 | CAUGHT |
| 改指标族名 / 删计数器预热 | CAUGHT |
| 删一条 rid trace 行 / 删 token id dump 点 | CAUGHT |
| 删日志组件前缀 / 改厂内环境变量名 | CAUGHT |
| 跨进程时间戳换回 `perf_counter` | SURVIVED（盲点，交给 L3） |
| 除法去掉兜零 | SURVIVED（盲点，交给单测或 L3） |

盲点不是放着不管，是**明确移交**：值失真那一类静态永远看不见，只能靠造流量后的 `/metrics`
前后 diff，或者该指标自己的单测。把盲点写进变异表，好处是下一轮谁想把它补上时，表里已经有
一条现成的失败样例。

## 判据顺序

1. L1 零退出码——不过就别往下走，缺的东西先补或先登记。
2. L2 残差逐条有解释，写进 `--accept` 清单或提交正文的「行为差」段。
3. 变异探针全部与预期一致——它不是每轮都跑，改过核对脚本或加过能力类之后必须跑。
4. L3 在有机器的时候跑，跑不起来记 deferred，不记 pass。
