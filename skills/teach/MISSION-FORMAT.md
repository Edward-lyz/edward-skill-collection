# MISSION.md Format

Optional scaffolding only. Create `MISSION.md` only when the learning goal is ambiguous and wrong scope would waste work. Most teach sessions should skip this file and start the Markdown lesson directly.

`MISSION.md` lives at the workspace root. It captures the reason the user is learning this topic.

## Template

```md
# Mission: {Topic}

## Why
{1-3 sentences. The concrete real-world goal. What changes when they have this skill?}

## Success looks like
- {A specific, observable outcome}
- {Another specific outcome}

## Constraints
- {Time, prior knowledge, preferences that bound the approach}

## Out of scope
- {Adjacent topics to avoid right now}
```

## Rules

- One mission per workspace.
- Concrete over abstract.
- Keep it under one screen.
- Revise when the goal changes.
