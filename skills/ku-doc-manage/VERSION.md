# 知识库文档管理 Skill - 版本记录

## 版本 2.20.0 (2026-09-23)

### ✨ 新增功能

#### 正文编辑支持 @人与 @引用文档
- 🙋 **@人**：`edit-mdsl-content` 的 `markdown` 内支持嵌入 `<mention uuap='UUAP' notify="true|false"></mention>` 提醒用户
  - `uuap` 必须由用户提供，禁止猜测；`notify` 默认 `false`（不通知），仅用户明确要求通知时才置 `true`
  - 支持同时 @ 多人（多个 `<mention>` 连写）或只 @ 单人，每人可单独设置 `notify`
  - 🔐 **@人后强制校验权限**：编辑并发布后，必须对被 @ 的 UUAP 调用 `query-permission`，对 `canRead=false` 的用户先向用户说明并询问是否添加权限，确认后再走 `add-member`，不擅自添加
- 🔗 **@引用文档**：用户提供知识库文档完整/短链接时，**库域名（`https://ku.baidu-int.com`）开头的裸链接原样写入 `markdown`，禁止套用标准 Markdown 链接 `[标题](url)`**（裸链接才会渲染成文档引用卡片）；非库域名外链按常规处理
- 📖 **规则沉淀**：`references/edit_content.md` 新增「@人与@引用文档」章节（语法、notify 默认值、单/多人示例、@人后权限校验流程、@文档保留裸链接规则），并在文档格式说明中补充指引

#### 查询数据表表夹下子表
- 🗂️ **新增 `get-datasheet-children` 子命令**：参考 `/ku/openapi/getDatasheetChildren` 接口，分页查询「数据表表夹」类型文档下的子表（数据表 / 仪表盘）列表
  - `--doc-id`（必填）：数据表表夹的文档ID，从数据表 URL 提取（`?tb=` 前的 path 段），与 `create-datasheet` 一致；非表夹类型文档会报错
  - `--page-num`（默认1）/ `--page-size`（默认10，最大100）：分页参数
  - 响应含 `pageNum` / `pageSize` / `hasMore` / `currentCount` / `data[]`，`data[]` 每项含 `nodeId` / `nodeName` / `nodeType`（2=数据表，4=仪表盘）/ `nodeTypeDesc`
  - 📌 **翻页规则**：以 `result.hasMore` 判断是否还有下一页；接口返回结果在源数据分页后按当前用户权限过滤，某页条数（`currentCount`）可能小于 `page-size`，不能据此判断是否查完
- 📖 **规则沉淀**：新增 `references/get_datasheet_children.md`，同步更新 `SKILL.md` 子命令速查表、`references/API_INDEX.md` 数据表管理类索引与场景4

## 版本 2.19.0 (2026-09-15)

### 🛡️ 稳定性

- 🇨🇳 **`create-doc --md-file` 兼容 Windows 常见文件编码**：自动识别并处理本地 Markdown 文件的编码，修复 Windows 用户 GBK 编码文件入库后乱码的问题
  - 文件带 UTF-8 BOM → 自动去除，BOM 不再进入文档内容
  - 文件为 GBK / GB2312 / GB18030 编码（Windows 记事本等默认保存格式）→ 自动转换为 UTF-8 后上传
  - 无法识别的编码按原字节处理，与旧行为一致；转码时在 stderr 输出提示
  - 新增依赖 `golang.org/x/text`（GB18030 解码器）
- 🚩 **命令行参数解析容错**：全部子命令改为统一走 `parseArgs`，修复两类参数被静默丢弃的问题
  - **布尔标志支持"空格+值"写法**：`--process-images true`、`--set-top true` 等写法不再导致解析提前停止。此前 Go 标准 flag 包会把 `true` 当作第一个位置参数并停止解析，**其后所有参数被静默丢弃**（如 `--process-images true --md-file xxx.md` 会导致 `--md-file` 失效、文件内容写不进去，只有把 `--md-file` 放到前面才正常）；现在自动归一化为 `--process-images=true` 后完整解析
  - **`--content` 支持 `\n` 转义还原**：字面 `\n`（反斜杠+n）自动还原为真实换行，修复 Windows 下 cmd.exe 对含真实换行的命令按行截断、多行内容只写入第一行的问题（如 `--content "line1\nline2"` 现在可完整写入）
- 📖 **文档同步**：`SKILL.md` 新增「参数写法约定」通用规则（布尔标志必须等号传值、多行内容用 `\n` 转义或 `--md-file`），`references/create_doc.md`、`references/API_INDEX.md` 同步补充传参约定说明

## 版本 2.18.0 (2026-09-03)

### ✨ 新增功能

#### 随心搭数据读取
- 🗂️ **`query-doc-resource` 支持读取随心搭数据**：参考 `/ku/openapi/queryDocResource` 接口新增的 `flexBuilderQueryType` / `keyPrefix` / `cursor` / `limit` 参数，随心搭组件的代码与组件内数据由**同一个接口**返回，不再分两次请求
  - `--flex-query-type` 支持 `code`（只取代码）/ `kv`（只取数据）/ `all`（两者），仅 `--resource-type flex-builder` 时有效
  - `--key-prefix` 按数据 key 前缀过滤
  - `--cursor` / `--limit` 游标分页，`limit` 取值 1-20000，不传时服务端默认 2000
  - 响应新增 `total` / `cursor` / `nextCursor` / `currentCount` 分页字段
  - 📌 **翻页规则**：以 `nextCursor` 是否返回判断是否查完，不能用 `currentCount < limit` 判断
  - 🚧 **参数隔离**：四个随心搭专用参数传给附件/图片/流程图/脑图等其他资源类型时直接报错，避免误用
- 📐 **资源 JSON 结构落档**：`downloadUrl` 下载到的 JSON 分 `code` / `kv` 两段，`references/query_doc_resource.md` 补齐两段的完整字段说明与真实样例
  - `code.content[]` 含 `id` / `code`（JSX 源码）/ `title` / `type` / `size`
  - `kv[]` 含 `key` / `value` / `createdBy` / `createdAt` / `updatedAt`
  - ⚠️ **`kv[].createdBy` 是用户 GUID（如 `wzXq-DUqOL`），不是邮箱**；组件写在 `value` 内的用户标识（如 `voterEmail`）才是邮箱。做身份过滤时用组件代码实际读写的字段，禁止拿 GUID 与邮箱比较
- 📖 **规则沉淀**：重写 `references/query_doc_resource.md` 随心搭章节（参数、数据分页、意图与参数对应表），同步更新 `SKILL.md` 随心搭意图分流、`references/query_content.md` 两步链路与 `references/API_INDEX.md` 场景 1.2

### 🔧 行为调整

- 🗣️ **面向用户统一说"随心搭数据"**：`KV` 只出现在参数值（`--flex-query-type kv`）与响应字段（`kv[]`）等技术位置；用户提到随心搭的"数据""内容""存了什么""结果""记录"等表述，或直接说"KV 数据"，都同样触发数据读取，各处文档不再单独解释这层对应关系
- 🧭 **"数据"与数据表的歧义规则**：用户只说"数据"时按目标文档实际内容判断——只有随心搭 → 随心搭数据；含数据表（URL 带 `tb=` / `type=dst`）→ 优先按数据表处理；两者都有且无法判断 → 向用户确认，不默认猜
- 📄 **读取全文时随心搭不再只报存在**：用户要求读取文档**全部内容**时，文档内随心搭默认一并取回组件代码与数据，并在输出中说明总条数与实际返回范围；用户只要正文、文档结构或组件清单时仍不取组件数据
- 🧠 **数据必须结合代码解读**：数据原始值无语义，key 命名规则、value 结构、字段含义均写在组件代码中，且代码可能存在按用户身份过滤展示的逻辑（如 `Ku.getUserInfo()` 按创建人/部门/白名单筛选）。要求先读代码再解读数据，结合当前用户身份确定实际可见范围，被过滤部分标注条数与原因，禁止直接抛出原始存储值
- 🚫 **写操作明确拒绝**：修改组件内数据归入"修改已有随心搭"分支，返回文档链接引导用户在页面内操作

### 🛡️ 稳定性

- 🔓 **权限校验交给 API**：随心搭数据的权限校验由接口统一处理，Skill 侧不做前置校验；接口报权限不足时按缺口分别引导（差管理员/创建者身份 → 联系管理员；是创建者但差编辑权限 → 申请文档编辑权限）
- 🧯 **数据读取失败不阻塞文档读取**：权限不足、组件不存在、文档已删除、接口限流、服务异常、数据解析失败等情况统一说明原因，不影响文档正文与其他可读资源的返回

## 版本 2.17.0 (2026-08-27)

### ✨ 新增功能

#### 成员管理支持如流群名称解析
- 🔍 **群名称自动解析为群号**：`add-member` / `update-member` 涉及如流群成员时，若用户提供的是如流群名称而非群ID，先通过 **企业搜索** 技能（enterprise-search）按群名称搜索解析出群号，再以群号作为 `memberGuid` / `username` 调用
- 🛡️ **防误传规则**：禁止把群名称直接当作群ID传入；搜索无结果或命中多个群时，向用户展示候选群（群名称+群号）确认后再执行
- 🔁 **不可用兜底**：企业搜索未安装、不支持搜如流群或调用失败时，直接请用户提供群ID（始终是最快兜底路径），不重试轰炸、不编造群号、不阻塞成员管理任务
- 📖 **规则沉淀**：在 `SKILL.md` 工作流新增"如流群名称解析"前置步骤，并更新 `references/add_member.md`、`references/update_member.md`

#### 知识本创建能力
- 📚 **`create-book` 创建知识本**：新增 `create-book` 子命令，参考 `/ku/openapi/createBook` 接口，在指定知识库的目标目录下创建知识本（目录型文档），可用于组织和管理子文档
  - `--repo-id` 必填，指定目标知识库
  - `--create-mode` 支持三种创建模式：`inherit`（权限继承，默认）/ `public`（公开）/ `private`（保密），同时兼容 1/2/3 整数写法
  - `--title` 默认"未命名知识本"，名称冲突时自动递增编号后缀
  - `--parent-doc-id` 默认创建到知识库根目录，支持在指定目录下创建
  - `--set-top` 支持置顶到当前目录
- 📖 **新增参考文档**：新增 `references/create_book.md`，并在 `SKILL.md` 与 `API_INDEX.md` 中登记该命令

#### 文档关联信息查询能力
- 🔗 **`query-relation` 查询文档关联信息**：新增 `query-relation` 子命令，参考 `/ku/openapi/queryRelation` 接口，分页查询指定文档的关联数据
  - `--doc-id` 必填，指定目标文档
  - `--type` 必填，关联类型：`link`（业务关联）/ `reference`（引用）/ `referenced`（被引用）/ `co_create`（共创）/ `read`（读取）
  - `--business-type` 业务来源，仅 `type=link` 时有效：`icafe` / `meeting` / `gitcase` / `iapi` / `purch`，不传返回全部来源
  - `--page-num` / `--page-size` 分页参数，`page-size` 最大 50
  - 📌 **翻页规则**：下游服务可能过滤数据导致当前页条数少于 `pageSize`，翻页判断以 `hasMore` 字段为准
- 📖 **新增参考文档**：新增 `references/query_relation.md`（含 8 类关联来源的字段结构说明与常见错误码），并在 `SKILL.md` 与 `API_INDEX.md` 中登记该命令

### ⚠️ 安全增强

#### 公开知识本二次确认
- 🔒 **公开模式确认**：`create-book` 使用 `create-mode=public` 创建公开知识本时，执行前必须通过 `AskUserQuestion` 向用户确认，避免知识本及其子页面企业内全员可见带来的信息泄露风险
