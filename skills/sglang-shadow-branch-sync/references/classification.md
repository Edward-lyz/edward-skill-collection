# 分类规范

## 判断顺序

先看这个提交“为什么存在”，再看它改了什么。

1. 内容确属上游 cherry-pick / merge → `[社区同步]`
2. 属于 EPD / 多模态 encoder / 视频图像预处理 → `[EPD]`
3. 属于监控、日志、指标、trace、调试打印 → `[监控]`
4. 属于 KV cache、radix、prefix cache、AS/AttentionStore → `[缓存]`
5. 属于 PD/PP 传输、连接、超时、重试、408、注册刷新 → `[PD传输]`
6. 属于流式输出、工具调用、约束解码、tokenizer/协议 → `[流式协议]`
7. 属于探活、实例信息、端口、启动参数、路由 → `[平台适配]`
8. 属于 CI、Dockerfile、镜像、依赖 pin、构建脚本 → `[构建]`
9. 属于测试用例、回归脚本 → `[测试]`
10. 属于吞吐、延迟、kernel、量化、融合、overlap、显存 → `[性能优化]`
11. 属于某模型的结构、权重、tokenizer、模型特有路径 → `[模型适配]`
12. 跨领域稳定性修复 → `[BUGFIX]`
13. 确实无法归类 → `[其他]`

## 边界规则

### 功能优先于修复

标题写 `fix` 不代表归 `[BUGFIX]`。看改动：

- 新增协议字段、新增接口、新增工具调用能力 → 归所属功能链路。
- 只改边界条件、空值、越界、未初始化内存、竞态 → 可能是 `[BUGFIX]`。
- 修的是某个功能内部的缺陷，且该功能本身也在本分支落地 → 随功能归组，
  避免同一个链路被拆到两处。

### `[BUGFIX]` 的边界

收：

- 调度器、KV allocator、内存安全、double free、OOM、死锁；
- 同时影响多个功能链路的稳定性修复；
- 无法归入任何单一交付链路的缺陷修复。

不收：

- EPD encoder 的缺陷（归 `[EPD]`）；
- cache 命中/驱逐的缺陷（归 `[缓存]`）；
- 工具调用/约束解码的缺陷（归 `[流式协议]`）；
- 只改 Dockerfile 的“修复”（归 `[构建]`）。

### `[社区同步]` 的边界

必须能指出上游来源：标题带 PR 号、`cherry-pick`、`pick ... from upstream`，
且 diff 与上游提交一致。内部聚合 merge（例如“Merge branch X into Y”）不算，
按它实际带入的内容归组。若一个 merge 同时带入多个领域，归 `[其他]` 并在
正文注明“聚合快照”，不要伪装成社区同步。

### `[PD传输]` 的边界

关键词不等于归属。只有改动落在传输/连接/超时语义上才归此类：

`common/conn.py`、`disaggregation/*`、mooncake/zmq/socket、`REQUEST_TIMEOUT`、
`batch_register`、`session_cooldowns`、`QuarantinedKV`、注册刷新。

只是把 KV 放进 cache 结构，仍归 `[缓存]`。

### `[缓存]` 的边界

收 KV cache、radix tree、prefix cache、AttentionStore/AS SDK、页表、命中率。
不收：

- `route_radix`（MoE 路由）——名字像 radix，实际是路由；
- DeepGEMM 编译缓存——归 `[构建]`；
- 压测脚本——归 `[测试]`。

### `[其他]` 的边界

只放真正无法归类的杂项。经验阈值：不超过来源提交总数的 3%。超过就回到
分类表重新判断，通常是 `[EPD]`、`[PD传输]` 或 `[构建]` 漏收。

## 真实边界案例

| 提交内容 | 错误归类 | 正确归类 | 依据 |
|---|---|---|---|
| encoder server 新增 1124 行、视频输入协议 | `[BUGFIX]` | `[EPD]` | 新功能，不是修复 |
| `prealloc_token_usage` 指标 | `[EPD]` | `[监控]` | 只加指标 |
| `_sync_budget` 添加后又被 revert | 分散在多组 | 净效应为零，归 `[缓存]` 并在正文注明 | tip 上已无该符号 |
| Dockerfile 里升级 flash_mla wheel | `[性能优化]` | `[构建]` | 只改镜像依赖 |
| `empty` 改 `zeros` 修 NaN | `[性能优化]` | `[BUGFIX]` | 未初始化内存 |
| 工具调用 keepalive 新环境变量 | `[模型适配]` | `[流式协议]` | 协议行为 |
| 内容检测 pipeline（新增包） | `[监控]` | `[其他]` | 独立功能，不是监控指标 |
| 8 卡 decode router 融合 kernel | `[平台适配]` | `[性能优化]` | kernel 改动 |

## 复核要求

分类完成后必须做代码级复核：

- 每个来源提交至少读文件列表与 25 行实际增删；
- 关键项展开完整 hunk；
- 复核报告必须给出 `sha10 + 文件/代码证据 + 建议类别`；
- 只有“标题看起来像”的结论一律作废。

复核结论落成覆盖表后重新生成整条链，不手改单条提交。
